# 长时间运行稳定性优化计划

本文是 HSVJEngine 的执行计划，目标是让 Android arm64 设备在持续播放、频繁切歌、采集热插拔、网络控制和输出后端切换场景下稳定运行。每一阶段都必须保留 `/api/v1` 唯一路径和 Java/C++ JNI 一对一关系。

## 当前基线（已完成）

- `python scripts/check_api_contract.py`：189 个后端 method/path，340 个 Web 调用点，25 个 Flutter 调用点通过。
- `python scripts/generate_api_reference.py --check`：通过。
- `python scripts/check_jni_contract.py`：48 个 Java native 声明与 48 个 C++ 导出一对一通过。
- `python scripts/check_architecture.py`：16 个 Native 模块、79 条显式 include 边通过。
- `node --test tests/*.test.mjs`：21 个测试通过。
- `:app:compileHw82BetaDebugJavaWithJavac` 与 `:app:externalNativeBuildHw82BetaDebug` 通过。

本轮已修复三个生命周期风险：HTTP Server 初始化不再使用捕获 `this` 的 detached thread；播放控制器排队切换线程归控制器所有并在析构时等待；解码器和帧释放任务纳入可等待的异步任务集合。

## 阶段一：线程与生命周期收敛（P0）

目标：任何业务对象销毁前，其后台任务、回调和文件描述符都能被停止并等待。

执行项：

1. 继续清理 Native 业务代码中的 detached thread，优先处理 `HttpServer_Material.cpp` 转码任务、`HttpServer_System.cpp` 重启任务和 `LayerVideo_Playback.cpp` 预加载任务。
2. 为长任务统一引入受所有者管理的 worker/future；禁止捕获裸 `this` 的后台任务跨过对象析构。
3. 为 Engine、NetworkManager、Mubu、Layer、Renderer 建立固定停止顺序，并在关闭日志中输出未完成任务数。
4. 将停止等待从固定 sleep 改成条件变量或任务计数，保留超时日志和故障上下文。

验收：重复启动/停止 1,000 次无线程泄漏；关闭时 pending task、active client、decoder release 均归零；AddressSanitizer/ThreadSanitizer（桌面桩构建）无新增报告。

## 阶段二：播放与资源状态机（P0）

目标：频繁切歌、自动续播和资源不足时保持状态一致，不产生僵尸解码器或错误音频路由。

执行项：

1. 将 `PlaybackRequestDispatcher`、`PlaybackCoordinator`、`LayerPlaybackController` 的状态转换整理成单一状态表。
2. 为每次播放切换分配 generation，旧请求的异步回调只能更新同一 generation。
3. 将 DecoderResourceGate 的占用、释放和超时统一接入诊断指标。
4. 增加播放状态、配置迁移和数据库事务测试。

验收：连续切换 10,000 次后活动解码器数回到初始值；播放、暂停、停止、自动续播的状态与 API 返回一致；异常文件和网络超时不阻塞后续请求。

## 阶段三：渲染与采集长稳（P1）

目标：Vulkan、DRM/KMS、Surface、V4L2、USB 采集在热插拔和设备丢失后可恢复。

执行项：

1. 为 Surface、DRM/KMS 两个输出后端建立互斥状态机和切换审计日志。
2. 检查所有 DMA-BUF plane、stride、modifier 的释放路径，统一纹理延迟销毁入口。
3. 为 V4L2/USB 采集增加设备断开、格式变化、空帧和恢复次数指标。
4. 将 Vulkan device lost、swapchain 重建和采集恢复纳入自动化演练。

验收：24 小时连续渲染无显存持续增长；模拟 100 次采集拔插后恢复率 100%；device lost 能触发既有 watchdog 恢复链路。

## 阶段四：API 字段契约（P1）

目标：在现有路径一对一基础上，实现请求字段、响应字段和错误码的一对一。

执行项：

1. 建立 `api/schema/`，以 JSON Schema/OpenAPI 描述稳定接口。
2. 后端统一校验必填字段、类型和范围；Web、Flutter 从同一 schema 生成模型或校验器。
3. 将错误码、分页、异步任务状态和版本兼容规则纳入 schema。
4. 扩展 `check_api_contract.py`，检查字段级漂移。

验收：任一接口 schema 变更能同时发现后端、Web、Flutter 不一致；禁止未登记字段和第二响应协议。

## 阶段五：打断模块循环依赖（P2）

目标：把当前 Native 大型循环依赖逐步变成单向依赖，降低回归范围。

执行项：

1. 先抽取 `contracts`：Playback、Layer、Render、DeviceStatus、Command。
2. Renderer 只接收 `RenderSceneSnapshot` 和 `RenderTarget`，不直接访问 Engine。
3. VOD 只依赖 repository 和 playback port，不直接依赖 Engine/具体 Layer。
4. NetworkManager 只管理传输和服务生命周期，HTTP 业务迁移到领域 adapter。

验收：核心业务模块不再形成强连通分量；至少 `playcontrol`、`database`、`renderer` 可在无 Android 设备环境下独立构建和测试。
