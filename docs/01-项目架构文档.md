# 项目架构文档

> 本文描述 2026-11-20 核对后的运行结构。模块源码与依赖详见 [02-模块开发参考](02-模块开发参考.md)，公开 HTTP method/path 详见自动生成的 [03-API接口规范](03-API接口规范.md)。

## 1. 交付边界

仓库包含五个需要同步维护、但产物和运行责任不同的交付边界。

| 边界 | 事实源 | 产物 | 运行职责 |
|---|---|---|---|
| Android 系统应用 | `app/` | 系统 APK | Activity/Surface 生命周期、JNI 装载、平台权限、系统服务与更新流程 |
| Native 引擎 | `include/`、`src/`、`shaders/`、`app/src/main/cpp/CMakeLists.txt` | `libhsvj_engine.so` 及 SPIR-V | 播放、采集、音频、图层、Vulkan 合成、协议服务和持久化 |
| 内嵌 Web 控制端 | `src/network/web/` | APK 内 Web assets | 桌面、移动、融合校正和点歌控制界面；只调用 `/api/v1` |
| Flutter 平板端 | `../Fultter_pad/` | 独立 Android APK | 通过 `8081/api/v1` 控制引擎，不持有播放或渲染状态 |
| ROM/vendor 集成 | `system-integration/hsvj-codec-vendor/`、`aosp_wfd_sink/` | vendor 共享库、系统服务及 ROM 配置 | 提供目标设备上的 FFmpeg/RKMPP/WFD、公开库和 SELinux 集成 |

`vendor/` 是 Native 引擎的第三方源码输入，不是第六个产品边界。`app/build/generated/`、SPIR-V 和版本头属于构建产物，不作为手工维护源。

## 2. 运行结构

```text
Android MainActivity / DrmKmsRenderService
                 |
                 | 49 组一一对应的 JNI 声明与导出
                 v
              Engine                         控制端
       +---------+----------+      Web / Flutter / TCP / UDP
       |         |          |                 |
       v         v          v                 v
     Mubu   CommandRouter  SystemConfig <- NetworkManager
       |         |          |                 |
       |         +----------+-----------------+
       v
 Layer / PlaybackRequestDispatcher / Decoder / Capture / Audio
       |
       v
 VulkanRenderer + RegionRotationRenderer
       |
       +-- Android Surface swapchain
       `-- DRM/KMS direct present
```

### `Engine`

`Engine` 是 Native 组合根和生命周期所有者。它创建并连接 `SystemConfig`、`Mubu`、`CommandRouter`、播放列表/VOD、场景、授权、效果、音频、网络所需对象以及 Android 下的 Vulkan 渲染器；初始化失败或退出时按相反方向停止网络、异步任务、图层、渲染器和业务对象。Java 层只负责驱动初始化、`update`、渲染和平台回调，不复制 Native 状态。

### `Mubu`

`Mubu` 是运行时图层容器。它按图层 ID 创建具体 `Layer`，持有图层对象和优先级顺序，并提供查询、删除、更新与可见图层快照。固定 ID 的类型和默认优先级只来自 `src/core/LayerDefinitions.cpp`，配置文件决定哪些授权图层实际创建和显示。

### `CommandRouter`

`CommandRouter` 把 HTTP、WebSocket、UDP、外设和命令文件的控制输入转换为领域操作，并持有 Engine/Mubu/配置/播放列表/区域渲染等非拥有指针。公开 HTTP 路由由 `HttpServer_*.cpp` 注册；模块动作只允许 `/api/v1/{module}/actions/{action}`，不得恢复数字命令或第二套响应协议。

## 3. 输出所有权

最终完整画面只有一个生产者：`Engine::renderFrame` 驱动 `VulkanRenderer`，按优先级将可见图层和切片合成到 canvas，再由 `RegionRotationRenderer` 处理区域映射、旋转、融合与校正。单个 Layer、Decoder、Capture 或 Android UI 都不直接提交最终显示帧。

Vulkan 有两个互斥的最终输出后端：

- Surface 模式：`ANativeWindow` 创建 Android Vulkan Surface 和 swapchain，由 Activity 的 Surface 生命周期管理。
- DRM/KMS 模式：`DrmKmsRenderService` 选择直接显示，Vulkan 向 KMS 输出缓冲提交；此时 Android Surface 销毁不会接管或中断当前 KMS 输出。

两种后端共享图层合成、区域处理和 Vulkan 设备资源，但一次运行只允许当前后端拥有 present。新增录屏、预览或镜像能力只能消费合成结果，不能形成第二条最终显示链。

## 4. 主要数据流

### 播放

```text
HTTP/场景/VOD/外设命令
  -> CommandRouter 或对应 HttpServer handler
  -> PlaybackRequestDispatcher / PlaybackCoordinator
  -> LayerVideo
  -> VideoDecoder / DecoderCore (FFmpeg + RKMPP)
  -> 解码帧或 DMA-BUF
  -> VulkanRenderer 纹理导入
  -> canvas/区域处理
  -> 当前输出后端
```

播放请求统一经过 playcontrol 的资源门和协调器；调用端不得绕过它另建一套播放状态。播放列表元数据由 `PlaylistManager`/数据库维护，运行中图层状态由 `LayerVideo` 和 Decoder 持有。

### 采集

```text
V4L2/USB 设备发现 -> V4L2Capture/UsbCapture
  -> 采集层 LayerVideo
  -> CaptureRenderer/Vulkan 采集纹理
  -> 与其他图层共同合成 -> 当前输出后端
```

采集层 10/11 仍是普通合成输入，不拥有屏幕。采集缓存、DMA plane、stride 和 modifier 必须沿现有结构传递，不能用宽高推断底层布局。

### 音频

```text
视频/纯音频解码 PCM 或 Android 蓝牙音频
  -> AudioPlayerManager 焦点与输出图层选择
  -> AudioPlayer/AAudio
  -> AudioProcessor
  -> EffectManager/AudioReactiveEngine
  -> 图层效果与 DMX 响应
```

`AudioPlayerManager` 是音频焦点和当前输出图层的协调点。Decoder、蓝牙和 VOD 不能各自长期占有独立输出路径。

### 配置与持久化

```text
config/config.json -> SystemConfig -> Engine/Mubu/Renderer/各管理器
HTTP 修改 ----------^       |
                              +-> SystemConfig::save

data/playlist.db -> PlaylistManager/VodDatabase
config/peripherals.json -> PeripheralManager
Scene/ -> SceneManager -> SystemConfig + 运行时图层
```

`SystemConfig` 是系统和图层配置的内存事实源；数据库只保存素材、播放列表和 VOD 关系数据。场景加载需要同时更新配置和运行态，不能只改 JSON 或只改 Layer。

## 5. 固定图层

| ID | 类型 | 别名 | 默认优先级 | 默认尺寸 | 语义 |
|---:|---|---|---:|---:|---|
| 1-4 | video | `Layer1`-`Layer4` | 10/20/30/40 | 1920x1080 | 主视频播放层 |
| 10-11 | video | `CaptureLayer`、`CaptureLayer2` | 10/11 | 1920x1080 | 实时采集层 |
| 21 | text | `LyricsLayer` | 21 | 1920x1080 | libass 歌词层 |
| 30 | text | `DanmakuLayer` | 30 | 1920x1080 | 弹幕层 |
| 31 | mirror | `MirrorLayer` | 31 | 1920x1080 | 投屏输入层 |
| 40 | text | `TextLayer` | 40 | 1920x1080 | 通用文本层 |
| 41 | text | `MessageLayer` | 90 | 800x200 | 启动、网络和授权提示；无授权也可用 |
| 50 | image | `BackgroundLayer` | 50 | 1920x1080 | 背景图片层 |
| 60 | image | `ImageLayer` | 60 | 1920x1080 | 内置图片/图片播放列表目标；始终可用 |
| 70 | image | `LogoLayer` | 70 | 320x180 | Logo 层 |
| 71 | qrcode | `QRCodeLayer` | 71 | 371x193 | 启动授权二维码；无授权也可用 |

新固定图层必须在 `LayerDefinitions.cpp` 增加唯一记录，并同步授权、配置、控制端和本文；禁止在 handler 或页面中另建冲突 ID 语义。

## 6. 网络端口

| 端口 | 协议/服务 | 当前用途 |
|---:|---|---|
| 8080 | HTTP | 调试/主 Web；控制流冻结时唯一保留的控制服务 |
| 8081 | HTTP | 移动 Web 与 Flutter；注册同一组 `/api/v1` 路由 |
| 9898 | HTTP，点歌相关 WebSocket 复用 | `/ktv`、`/vod` 页面及 API；仅在 VOD 启用时启动 HTTP 服务。`NetworkManager` 当前把 `wsPort_` 设为 9898，因此不再单独启动 `WebSocketServer` |
| 8090 | WebSocket 默认/可选端口 | `WebSocketServer` 和发现协议保留的独立默认值；当前 `NetworkManager` 默认运行配置未监听该端口 |
| 9000 | TCP | 中控配置/外设触发消息，不直接接 `CommandRouter` |
| 8000 | UDP | 命令输入，接入 `CommandRouter` |
| 4322 | UDP 组播/单播 ACK | 多设备同步组专用端口；Leader 组播成功命令，Follower 回 ACK。仅在 `syncGroup.enabled=true` 时监听，发现结果未启用时 `ports.sync=0` |

设备发现自身监听 UDP `18080`，并在 `ports.sync` 发布同步端口；同步未启用或启动失败时发布 `0`。修改端口时必须同步 `NetworkManager`、`DeviceDiscoveryService`、控制端配置和本文，不能只改注释或单个默认参数。

## 7. 代码与文档守门

联调工程位于 `D:\HVIDEO`。播放器为 `Hplayer`，控制 PAD 为 `Fultter_pad`，点歌 PAD 为 `Fultter_pad_vod`，点歌服务器为 `Hvideo_server`，分布式系统为 `Distributed Matrix System`。控制 PAD 通过播放器的 8081 端口访问 `/api/v1`。

- CMake 模块边界：`python scripts/check_architecture.py`
- HTTP 后端/Web/Flutter 一一对应：`python scripts/check_api_contract.py`
- API 文档与路由一致：`python scripts/generate_api_reference.py --check`
- Java/C++ JNI 一一对应：`python scripts/check_jni_contract.py`
- 架构优点、现存问题和演进顺序：[05-架构评估与技术债](05-架构评估与技术债.md)

删除能力时要同时删除声明、实现、调用点、构建项和文档；新增兼容路径必须有已发布版本依据和明确移除期限。
