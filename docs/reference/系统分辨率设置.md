# 调试网页系统分辨率

入口：系统设置 → 公共配置 → 显示配置 → 系统分辨率。

选择并确认后立即切换和保存，无需再点公共配置的保存按钮。重新进入显示配置会回读系统状态；失败显示错误并允许重试。

唯一 HTTP 接口：

- `GET /api/v1/system/display-resolution`：读取当前主屏模式与候选列表。
- `POST /api/v1/system/display-resolution`：仅接受 `{"mode":"3840x2160p30.00"}`，模式必须来自 GET 的 `modes`。不接受额外字段。

响应使用现有统一 envelope，data 为：

```json
{"mode":"1920x1080p60.00","modes":["3840x2160p60.00","3840x2160p30.00","1920x1080p60.00"],"read_only":false}
```

JNI 经 HSVJEngine → PlatformControlGateway → SystemDisplayResolution 调用与 TvSettings 相同的 `android.os.RkDisplayOutputManager`：`getIfaceList`、`getCurrentInterface`、`getModeList`、`getCurrentMode`、`setMode`、`saveConfig`。目标是当前主屏 display=0；HDMI 候选与 ROM 的 DrmDisplaySetting 一致，MIPI 为固定分辨率，只读。原始模式尾部索引和刷新率小数按系统规则归一化。当前为 Auto 或其他非候选模式时单独显示当前值，不冒充已选择某一手动模式。

非法模式和参数返回 400；系统服务不可用、模式列表为空、切换未生效、保存失败返回 503。切换后最多等待两秒回读，匹配才调用 saveConfig；失败尝试恢复先前模式。写请求不自动重试，响应丢失后重新读取。网页确认发生在切换之前，本功能不新增系统设置的十秒预览倒计时。

不写 config.json 的渲染分辨率、不调用 wm size、不操作显示属性或分区、不新增 ROM 接口。
