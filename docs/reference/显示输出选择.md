# HDMI / MIPI 显示输出选择

调试网页入口：系统设置 → 公共配置 → 显示配置 → 显示输出。

显示输出、合成帧率和渲染质量在同一行操作，窄屏自动换行。选择 HDMI 或 MIPI 后立即保存到系统，并询问是否重启设备。取消重启保留已保存选择，仅此时显示“待重启”和“重启”按钮；悬停状态可查看本次启动实际输出。正常状态不显示重复说明或刷新按钮，读取失败时提供“重试”；重新打开显示配置也会读取系统状态。普通公共配置保存不重复写入此选项。

## 唯一接口

`GET /api/v1/system/display-output` 读取系统保存的选择。

`POST /api/v1/system/display-output` 只接受一个字段：

```json
{"mode":"mipi"}
```

`mode` 仅为小写 `hdmi` 或 `mipi`，不接受附加字段。两种请求的成功响应使用现有统一响应封装，`data` 为：

```json
{"mode":"mipi","active_mode":"hdmi","reboot_required":true}
```

- `mode`：系统保存的下次启动输出选择。
- `active_mode`：`ro.boot.hsvj_output` 本次启动值；无法识别时为空字符串。
- `reboot_required`：保存值与当前启动值是否不同；当前启动值未知时为 true。

非法参数 HTTP 400；系统服务不可访问、拒绝请求、超时或响应无效时 HTTP 503，不伪造默认成功。POST 成功不自动重启。用户在网页确认后复用 `POST /api/v1/system/reboot`，不新增重启接口。

## 与 Android 系统设置一致

播放器与 TvSettings 都访问 init 管理的 `/dev/socket/hsvj_outputd`，协议为 `GET\n` / `SET hdmi\n` / `SET mipi\n`，成功回复为 `OK hdmi\n` / `OK mipi\n`。由原有系统服务负责写入和回读验证 `lcdparam`；网页不直接操作分区、不保存第二份 config.json 输出配置、不切换播放器渲染后端。

客户端连接、发送、完整接收共用 3 秒期限；处理分片回复、错误回复、截断和超长回复。系统服务继续限制为 root/system UID。播放器当前系统签名共享 UID 为 1000。

系统启动仍通过原有 U-Boot 输出选择机制使用对应 HDMI/MIPI 设备树。本次只修改播放器 APK 和网页，不修改 ROM、内核、系统选择服务或构建链。
