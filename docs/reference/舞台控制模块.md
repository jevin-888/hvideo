# 舞台控制模块

舞台控制模块以视频播放时间为时间轴，在视频播放过程中按 Cue 顺序触发内部特效或外部通信动作。网络和串口发送在独立工作线程执行，不阻塞渲染循环。

## 配置文件

配置文件名为 `stage_control.json`，保存于 `CONFIG_DIR/stage_control.json`，当前配置版本为 2。设备默认根目录下的实际路径通常是 `/huoshan/config/stage_control.json`；若未挂载 `/huoshan`，则使用 `/sdcard/huoshan/config/stage_control.json`。如果 Java 层传入了自定义根目录，则实际路径为 `<根目录>/config/stage_control.json`。舞台控制不再使用全局视频图层时间轴，而是使用“播放列表 + 播放列表视频条目”绑定独立 Cue：

```json
{
  "version": 2,
  "enabled": true,
  "tolerance_ms": 80,
  "bindings": [
    {
      "playlist_id": "playlist-opening",
      "playlist_item_index": 0,
      "media_uri": "/huoshan/materials/opening.mp4",
      "media_title": "开场视频",
      "cues": [
        {
          "id": "cue-opening",
          "name": "开场",
          "time_ms": 1000,
          "enabled": true,
          "actions": [
            {
              "kind": "effect",
              "layer_id": 1,
              "effect_no": 3,
              "effect_params": {}
            },
            {
              "kind": "protocol",
              "protocol": "udp",
              "mode": "direct",
              "encoding": "text",
              "address": "192.168.1.100",
              "port": 9000,
              "payload": "START"
            }
          ]
        }
      ]
    }
  ]
}
```

- `playlist_id` 和 `playlist_item_index` 是视频绑定主键；同一视频出现在不同播放列表或同一列表的不同条目时，时间轴仍然相互独立。
- `media_uri` 是绑定时保存的视频路径。运行时会同时校验播放列表、条目索引和当前媒体路径，避免播放列表调整后误触发原时间轴。
- `time_ms` 为从当前视频开始计算的毫秒数。
- `tolerance_ms` 用于补偿渲染帧间隔，允许范围为 `0`～`2000`。
- Cue 会按 `time_ms` 排序；同一个视频绑定内的 Cue ID 必须唯一，且只能包含字母、数字、`.`, `_`, `-`。
- 一个 Cue 可以包含多个动作，动作按数组顺序执行。
- 舞台控制页面复用播放列表现有 API：`GET /api/v1/playlists` 和 `GET /api/v1/playlists/{id}/items`，不重复增加播放列表查询接口。
- 旧版 `version: 1` 全局 `source_layer_id/cues` 配置不会自动迁移或触发，请在页面中重新选择播放列表视频并保存，避免旧 Cue 误绑定到其他视频。

## 动作类型

### 内部特效

```json
{
  "kind": "effect",
  "layer_id": 1,
  "effect_no": 3,
  "effect_params": {}
}
```

内部特效复用渲染模块 `set_effect` 命令，不重复实现特效逻辑。

### UDP

直发：

```json
{
  "kind": "protocol",
  "protocol": "udp",
  "mode": "direct",
  "encoding": "text",
  "address": "192.168.1.100",
  "port": 9000,
  "payload": "START"
}
```

广播：将 `mode` 改为 `broadcast`，使用外设模块已连接的 UDP 客户端列表；组播：使用 `mode: "multicast"`、`multicast_group` 和可选 `ttl`。

### TCP

支持 `direct` 和 `broadcast`：

```json
{
  "kind": "protocol",
  "protocol": "tcp",
  "mode": "direct",
  "encoding": "hex",
  "address": "192.168.1.101",
  "port": 9100,
  "payload": "AA 55 01 00 FF"
}
```

### WebSocket

当前支持向已连接的 WebSocket 客户端广播：

```json
{
  "kind": "protocol",
  "protocol": "websocket",
  "mode": "broadcast",
  "encoding": "text",
  "payload": "{\"event\":\"show-start\"}"
}
```

### RS232 / RS485

串口动作使用 `serial_port` 和 `baudrate`：

```json
{
  "kind": "protocol",
  "protocol": "rs232",
  "encoding": "hex",
  "serial_port": "/dev/ttyS3",
  "baudrate": 115200,
  "payload": "01 02 03 04"
}
```

RS485 使用相同的串口发送适配器；模块不会重复实现串口打开、波特率校验和写入逻辑。

## HTTP API

公开 API 只有统一的模块动作端点：

```text
POST /api/v1/stage-control/actions/{action}
```

请求体只包含动作参数，不携带 `type`、`code`、`param` 或顶层 `action` 字段。可用动作：

- `get_config`：读取配置和运行状态。
- `replace_config`：校验并整体替换配置，参数为 `{ "config": { ... } }`。
- `set_enabled`：启用或停用，参数为 `{ "enabled": true }`。
- `arm`：布防时间轴。
- `disarm`：撤防并清理当前时间轴状态。
- `reset_timeline`：重置已触发 Cue。
- `preview_cue`：立即预览单个 Cue，参数为 `{ "cue": { ... } }`。

## 时间轴行为

- 播放开始后，只有当前播放列表和当前视频条目匹配 `bindings` 时，该视频自己的 Cue 才会在时间穿越其 `time_ms` 时触发。
- 首次接入时不会把当前播放位置之前的全部 Cue 补发，只会检查当前容差窗口。
- 播放时间回退、切换播放列表视频条目、媒体路径变化或执行重置时间轴时，对应视频的已触发 Cue 集合会清空。
- 暂停期间不读取并触发时间轴；恢复播放后继续检测。
- 撤防、停用、替换配置时会清空待执行 Cue 队列。
- 协议发送失败不会阻止同一 Cue 的后续动作，状态中会保留首个错误信息。
