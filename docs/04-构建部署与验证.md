## 2. Android APK

有效变体只有：

| 变体 | 硬件/签名 | 用途 |
|---|---|---|
| `hw81BetaDebug` | hw81 | 调试 |
| `hw82BetaDebug` | hw82 | 调试 |
| `hw81StableRelease` | hw81 | 正式 |
| `hw82StableRelease` | hw82 | 正式 |

```powershell
.\gradlew.bat :app:assembleHw81BetaDebug --no-daemon
.\gradlew.bat :app:assembleHw81StableRelease --no-daemon
```

版本从 `1.0.1` 开始，每次成功打包 APK/AAB 自动递增一次：`1.0.9 → 1.1.0`、`1.9.9 → 2.0.0`。同一次 Gradle 构建的 hw81/hw82 和不同通道共用版本；失败构建、仅 clean、同步、检查及 `--dry-run` 不消耗版本。`app/version.properties` 记录上一次成功打包的版本，缺失时从 `1.0.0` 起算。`VERSION_CODE` 是独立递增的 Android 安装编号，重置显示版本时保留它，确保可以覆盖旧包。无需传入版本递增参数。

ROM 内置编解码栈时避免 APK 重复携带 FFmpeg/RKMPP：

```powershell
.\gradlew.bat :app:externalNativeBuildCleanHw81StableRelease `
  :app:assembleHw81StableRelease `
  -PuseSystemCodecStack=true --no-daemon --stacktrace
```

`copyWeb` 把 `src/network/web` 放入 generated assets；Shader sync 任务把 CMake 生成的 SPIR-V 放入 generated assets。禁止把生成结果复制回源码树。

播放器每次启动、初始化 Native/Web 服务前，`IncrementalUpdater` 都直接枚举当前 APK 的 `assets/web`，对 `/huoshan/web` 对应文件做完整 SHA-256 校验，APK 版本和资源清单未变化也不跳过。文件缺失、空文件、截断或内容不一致时，使用 APK 原文件自动修复；正常文件不重复写入。同步时的 Web 清单也直接来自 APK，避免不完整的资源分类结果漏掉文件。

Web 修复先写同目录 `.hsvj-web-tmp` 文件，执行文件 `fsync`、完整哈希校验后原子替换目标；失败清理临时文件并保留原文件。全部 Web 文件复核通过才保存资源清单。资源同步失败时，普通 Surface 和 DRM/KMS 两条启动路径均停止本次 Native 初始化并记录错误。该机制仅校验 APK 管理的 Web 文件，不新增 API，不以 APK 默认配置覆盖现有用户配置、授权或数据库。

## 4. ROM vendor 编解码栈

### HSVJ / H66_POR 正式 ROM 入口

当前正式 ROM 使用 `D:\HVIDEO\HSVJ\build_hsvj_rom.ps1`。脚本先从当前 `D:\HVIDEO\Hplayer` 构建 hw81 正式 APK，并生成输入快照与构建回执，再进入 WSL 的 `/mnt/d/HVIDEO/HSVJ/android11-hsvj-src` 编译 `h66_por-user`。输出目录是 `out-hsvj-user`；ROM 按 `D:\HVIDEO\HSVJ\update_vNN.img` 交付，构建记录位于 `D:\HVIDEO\HSVJ\records`。

例如生成尚不存在的 V25：

```powershell
& 'D:\HVIDEO\HSVJ\build_hsvj_rom.ps1' -ReleaseVersion v25 -Jobs 4
```

每次发布选择未使用的版本号。正式流程重建 APK、U-Boot、boot 和 Android 分区，使用校验锁定的稳定内核、HDMI/MIPI 设备树及其余参考启动镜像，最终解包比对九个条目。仅打包模式不可用于发布新的 ROM。

`/home/jevin/android11-firefly-hsvj` 及 `rom_build_records` 中旧的 `h66_por-userdebug`、固定 `update.img`、八条目构建记录属于历史流程，不是当前正式版入口；历史变更账本中的路径不应作为新版本构建依据。

### 编解码运行时

`system-integration/hsvj-codec-vendor` 的运行时闭包固定为：

```text
libmpp.so
libavcodec.so
libavformat.so
libavutil.so
libswscale.so
libswresample.so
```

`AndroidProductCopyFiles.mk`、`vendor/etc/public.libraries.txt`、`sepolicy/file_contexts` 和 `vendor/lib64` 必须包含相同六项。具体产品树接入见该目录 README。

## 5. 提交前检查

```powershell
python scripts/check_api_contract.py
python scripts/generate_api_reference.py --check
python scripts/check_jni_contract.py
python scripts/check_architecture.py
python scripts/check_source_encoding.py
node scripts/test_capture_edid_web.cjs
node scripts/test_scene_save_web.cjs
```

独立 Hplayer CI 使用 `python scripts/check_api_contract.py --player-only`。联调时运行默认命令核对同级 Flutter 源码和生成文档。CI 编译正式变体需要设置 `LICENSE_HMAC_KEY`。

完整 Web 回归使用 Node.js、Microsoft Edge、Acorn 和 Playwright。测试依赖可用 `npm install --no-save --no-package-lock acorn@8.15.0 playwright@1.57.0` 安装。运行 `scripts/test_*.cjs` 时，可通过 `EDID_QA_OUTPUT`、`LAYER_CONTROLS_QA_OUTPUT`、`MATERIAL_BROWSER_QA_OUTPUT`、`SERIAL_TEMPLATE_QA_OUTPUT` 或 `I18N_SCREENSHOT_DIR` 指定截图输出目录。

Flutter 改动另执行 `flutter analyze`；Native/Android 改动至少构建一个对应硬件变体。涉及 Surface、DRM/KMS、V4L2、RKMPP、串口、系统设置、看门狗或 ROM 的改动必须真机验收，桌面静态检查不能替代设备验证。

## 6. API 变更流程

1. 在唯一 `HttpServer_*.cpp` 处理器注册 method/path。
2. 删除被替代的旧路由和响应字段，不新增兼容别名。
3. 同步 Web/Flutter 唯一调用点。
4. 运行 `python scripts/generate_api_reference.py` 更新路由文档。
5. 运行 API 和 JNI 契约检查。

## 7. 清理约束

- 构建输出只存在于 `build`、`.cxx`、`.gradle`、`.dart_tool`、`out` 等忽略目录。
- 设备日志、截图、反编译目录、一次性补丁和诊断 HTML 不提交。
- 第三方依赖保留构建所需源码和许可证，不保留上游 tests/examples/benchmarks。
- 自动化回归源码集中在 `scripts/`、`tests/` 和相应的 `system-integration/` 目录。将测试生成物放到临时目录并在运行结束后清理。
