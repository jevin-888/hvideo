# 架构评估与技术债

评估日期为 2026-11-20。运行入口、调用方向与交付边界见 [项目架构文档](01-项目架构文档.md)，Native 各模块的职责和依赖见 [模块开发参考](02-模块开发参考.md)。

## 已收敛的边界

| 边界 | 本轮核对结果 |
|---|---|
| Native 模块 | 16 个 CMake 模块、80 条直接 include 依赖与声明一致。数据库经 `foundation/CloudMaterialMetadata.h` 使用云端素材数据结构。音频模块只链接自身所需的组件，输出图层选择策略由 Core 持有。 |
| Android/JNI | Surface 和 DRM/KMS 共用资源准备入口，Java 声明与 C++ JNI 导出一一对应，共 49 组。Vulkan 持有最终合成画面，由当前启用的单一后端提交显示。 |
| HTTP/API | 检查了 200 个后端 method/path、206 个 Web 字面量调用和 25 个 Flutter 字面量调用。接口规范由源码生成，已纳入一致性检查。 |
| Web | 桌面、移动、融合校正共用请求实现，桌面和移动入口各自配置认证。移动首页保留播控、场景和视频三组页面，矩阵编辑、投影校正、外设和系统配置等完整入口由桌面端维护。 |
| 构建与 ROM | Web 和 SPIR-V 在构建期打包，系统应用按硬件变体输出正式 APK。FFmpeg/RKMPP 由目标 ROM 的 vendor 层提供，复制规则、公开库、SELinux 和实体文件的对应关系由 ROM 集成脚本检查。 |
| 回归验证 | Hplayer 独立仓库的 CI 运行 `--player-only` API 检查和 JavaScript 回归，设置构建密钥后亦编译正式变体。联调工作区的默认 API 检查同时核对同级 Flutter 控制端和接口文档。 |

## 剩余事项

| 优先级 | 问题与代码证据 | 影响及改造边界 |
|---|---|---|
| 高 | `core`、`layer`、`lyric`、`network`、`playcontrol`、`renderer`、`text`、`vod` 仍处于同一个强连通组。`renderer` 读取 Core 配置和图层对象，`playcontrol` 与 `vod` 双向依赖，`network` 的部分 handler 直接调用 Core 和图层对象。 | 拆分时先明确渲染所需的只读参数、播放请求与结果的所有者，再迁移调用方。涉及输出、重入和停止顺序的变更需要在两种硬件上回归。 |
| 高 | `core` 负责 Engine 组装、命令、场景、授权和外设，`layer` 同时持有模型、播放和渲染状态，`network` 同时实现传输、HTTP 业务、VOD 和云同步。 | 按启动与停止顺序梳理所有权，将 HTTP 业务逐步交由对应领域处理，端口及连接生命周期由 NetworkManager 管理。 |
| 高 | HTTP method/path 可以自动核对，字段、响应和错误码仍主要由 C++ handler 与客户端分别处理。部分调用路径动态生成。 | 参数改动可能在各客户端间漂移。先为常用接口建立字段级契约和错误响应回归。 |
| 中 | `NetworkManager` 创建 8080、8081、9898 三个 `HttpServer` 实例并分别注册路由。8080 承载调试 Web，8081 提供移动 Web 与 PAD 控制，9898 按点歌启用状态启停。 | 整理路由表时要按端口核对静态资源、认证、SSE、WebSocket、发现协议和冻结控制流的行为。 |
| 中 | 部分 CMake 模块将实际链接和 include 依赖契约分别声明。仅头文件依赖与实际链接依赖的集合可能不同。 | 新增 include 或链接关系时同步检查这两类声明，继续用架构检查对照源码。 |
| 中 | 系统应用依赖平台签名、privileged 权限和厂商 WFD/DRM/RKMPP 接口。真实 PAD、服务器和播放器链路需要现场环境。 | 主机回归覆盖协议和部分故障路径，Surface/DRM 输出、硬解、采集和联调仍需要对应 ROM 与设备。 |
| 低 | `Fultter_pad` 路径已被现有脚本、文档和工具引用。 | 如调整目录名，同步迁移这些引用。当前联调目录见 [项目架构文档](01-项目架构文档.md)。 |

## 验证入口

- `python -B scripts/check_architecture.py` 核对模块声明、平台操作所有权、生成物和 jsoncpp 所有权。
- `python -B scripts/check_api_contract.py` 核对 Hplayer 和同级 Flutter。独立检出使用 `--player-only`。
- `python -B scripts/generate_api_reference.py --check` 核对生成的接口文档。
- `python -B scripts/check_jni_contract.py` 核对 Java/C++ 导出和关键回调签名。
- 正式构建与设备联调入口见 [构建部署与验证](04-构建部署与验证.md)。
